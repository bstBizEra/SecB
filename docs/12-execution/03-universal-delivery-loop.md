# Universal Delivery Loop

## Canonical loop

```text
1. INTENT — capture desired outcome
2. REGISTER — bind project, product, module and owner
3. FRAME — define problem, stakeholders and constraints
4. RESEARCH — establish facts, unknowns and sources
5. OPTIONS — compare viable approaches
6. DECIDE — record decision, rationale and authority
7. DESIGN — define contracts, architecture or process
8. PLAN — create ordered, testable work packages
9. AUTHORIZE — issue roles, scope, budget and evidence obligations
10. EXECUTE — perform bounded work
11. SELF-VERIFY — producer runs fresh checks
12. REVIEW — independent conformance and quality challenge
13. ASSURE — QA, SEC and DOMAIN verification
14. GOVERN — approve, reject, accept risk or replan
15. DELIVER — integrate, release or submit artifact
16. OBSERVE — measure technical and business outcome
17. LEARN — extract experience and causal lessons
18. KNOWLEDGE — curate validated claims
19. SKILL — package repeatable procedure
20. IMPROVE — update goals, controls, tools and workflows
```

## Inner Engineering Loop Binding

Steps 10-12 (EXECUTE, SELF-VERIFY, REVIEW) operate under the **[bOPEN Engineering Loop (BOPEN-ENG-LOOP-001)](08-bopen-engineering-loop.md)** state machine (`GOAL` ➔ `PLAN` ➔ `ACT` ➔ `VERIFY` ➔ `V == Spec ? DONE : PLAN`) with Evidence-Based Independent Verification (`BOPEN-GOV-EBIV-001`).

## Loop invariants

- Every state has an accountable owner.
- Every transition has criteria and evidence.
- Every mutation has bounded authority.
- Every failure has a learning disposition.
- Every completion has an outcome receipt.
- Every promoted skill has evaluation and revocation controls.
