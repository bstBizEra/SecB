# Skill Lifecycle

```text
DISCOVER
→ SOURCE_PINNED
→ INTAKE_REVIEW
→ ADAPTED
→ BASELINE_FAILURE_TESTED
→ SKILL_ENABLED_TESTED
→ CROSS_HARNESS_EVALUATED
→ SECURITY_REVIEWED
→ RESTRICTED_PILOT
→ APPROVED
→ PUBLISHED
→ MONITORED
→ UPDATED / DEPRECATED / REVOKED
```

## Skill package requirements

- immutable skill ID and semantic version;
- purpose, scope and non-goals;
- inputs, outputs and schemas;
- instructions and workflow;
- model/harness compatibility;
- tool, MCP, filesystem, network and credential permissions;
- test and pressure scenarios;
- expected evidence;
- provenance and license;
- known limitations;
- approval, deprecation and revocation state.

## Promotion criteria

A skill is publishable only when it is repeatable, bounded, testable, secure, evidence-backed and independently reviewed. Broad publication requires cross-project applicability evidence; otherwise publish with restricted project scope.
