# Detailed Workflow — Architecture Roadmap and Work-Package Compilation

## Preconditions

- Confirm: architecture baseline.
- Confirm: decision records.
- Confirm: risk register.
- Confirm: delivery constraints.
- Confirm: governance gates.

## Detailed checks

- Define target outcomes and the architecture baseline each work package assumes.
- Decompose work by cohesive capability, contract, dependency, and verification boundary.
- Identify critical path, parallel lanes, integration points, migration steps, and rollback needs.
- Assign producer, reviewer, QA, security, operations, domain, and governance responsibilities by risk.
- Define deliverables, explicit exclusions, declared write sets when applicable, and acceptance criteria.
- Define verification methods, evidence requirements, entry conditions, exit gates, and blocked dependencies.
- Produce roadmap waves and work-package candidates without implying authorization.

## Anti-patterns

- Starting implementation before the architecture scope and authority are established.
- Treating plausible inference as verified fact.
- Hiding uncertainty or adverse consequences.
- Using a framework mechanically when it does not answer the stakeholder question.
- Declaring approval, conformance, or activation outside assigned authority.
- Passing secrets, hidden reasoning, or unrestricted context through handoffs.

## Handoff minimum

- Source and destination role
- Objective, scope, baseline, and status
- Artifacts and evidence references
- Decisions and assumptions
- Risks, limitations, and unresolved items
- Required next action and acceptance criteria
